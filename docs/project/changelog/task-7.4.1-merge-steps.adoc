`mergeV()` and `mergeE()` provide upsert semantics: find an existing element matching
a search predicate and return it, or create a new one if none matches.
They were introduced in TinkerPop 3.6 and significantly stabilised in 3.8.x with
documented `onCreate` / `onMatch` option semantics.
These steps are a common production pattern for idempotent data loading.

== Background

=== The Problem `merge` Steps Solve

Without merge steps, idempotent upsert requires two traversals:

[source,kotlin]
----
// Pre-merge pattern — verbose and not atomic
val existing = g.V().has("email", "alice@example.com").tryNext()
if (existing != null) {
    existing.property("lastSeen", now)
} else {
    g.addV("person").property("email", "alice@example.com").property("lastSeen", now)
}
----

With `mergeV()`:

[source,kotlin]
----
g.mergeV(mapOf(T.label, "person", "email", "alice@example.com"))
    .option(Merge.onCreate, mapOf(T.label, "person", "email", "alice@example.com", "created", now))
    .option(Merge.onMatch, mapOf("lastSeen", now))
    .next()
----

=== 3.8.x Semantics

`mergeV(searchCriteria)`:

1. Search for a vertex whose properties include all key/value pairs in `searchCriteria`.
2. If found → apply `onMatch` properties to the matched vertex and return it.
3. If not found → create a new vertex using `onCreate` properties (or `searchCriteria` if `onCreate` is absent) and return it.

`mergeE(searchCriteria)`:

1. Search for an edge matching `searchCriteria` (which may include `Direction.OUT` and `Direction.IN` vertex references).
2. If found → apply `onMatch` properties and return it.
3. If not found → create a new edge using `onCreate` properties and return it.

Step execution logic:

[source,kotlin]
----
class MergeVertexStep(
    private val searchCriteria: Map<Any, Any?>,
    private val onCreateProps: Map<Any, Any?>?,
    private val onMatchProps: Map<Any, Any?>?
) : Step<Vertex, Vertex> {

    override fun processNextStart(): Traverser<Vertex> {
        // 1. Extract label from search criteria (T.label key or "label" string)
        val label = searchCriteria[T.label] as? String ?: Vertex.DEFAULT_LABEL

        // 2. Find candidate vertices
        val propertyFilters = searchCriteria
            .filterKeys { it != T.label && it != T.id }
            .map { (k, v) -> k.toString() to v }

        val candidates = graph.vertices().asSequence().filter { v ->
            v.label() == label &&
            propertyFilters.all { (k, v2) -> v.value<Any?>(k) == v2 }
        }.firstOrNull()

        return if (candidates != null) {
            // onMatch: apply update properties
            onMatchProps?.forEach { (k, v) ->
                if (k != T.label && k != T.id) candidates.property(k.toString(), v)
            }
            DefaultTraverser(candidates)
        } else {
            // onCreate: create with provided properties
            val createProps = onCreateProps ?: searchCriteria
            val vertex = graph.addVertex(createProps.mapKeys { it.key.toString() })
            DefaultTraverser(vertex)
        }
    }
}
----

=== 3. `mergeE()` Step

`mergeE()` supports additional keys in the search map:

* `Direction.OUT` → the out-vertex (a `Vertex` instance or vertex ID)
* `Direction.IN` → the in-vertex

[source,kotlin]
----
class MergeEdgeStep(
    private val searchCriteria: Map<Any, Any?>,
    private val onCreateProps: Map<Any, Any?>?,
    private val onMatchProps: Map<Any, Any?>?
) : Step<Edge, Edge> {

    override fun processNextStart(): Traverser<Edge> {
        val label = searchCriteria[T.label] as? String
            ?: throw IllegalArgumentException("mergeE requires T.label in search criteria")

        val outV = resolveVertex(searchCriteria[Direction.OUT])
        val inV  = resolveVertex(searchCriteria[Direction.IN])

        val propertyFilters = searchCriteria
            .filterKeys { it !in setOf(T.label, T.id, Direction.OUT, Direction.IN) }

        val candidate = graph.edges().asSequence().firstOrNull { e ->
            e.label() == label &&
            (outV == null || e.outVertex() == outV) &&
            (inV  == null || e.inVertex()  == inV ) &&
            propertyFilters.all { (k, v) -> e.value<Any?>(k.toString()) == v }
        }

        return if (candidate != null) {
            onMatchProps?.forEach { (k, v) -> candidate.property(k.toString(), v) }
            DefaultTraverser(candidate)
        } else {
            requireNotNull(outV) { "mergeE: out-vertex is required for creation" }
            requireNotNull(inV)  { "mergeE: in-vertex is required for creation"  }
            val createProps = (onCreateProps ?: searchCriteria)
                .filterKeys { it !in setOf(T.label, T.id, Direction.OUT, Direction.IN) }
                .mapKeys { it.key.toString() }
            val edge = outV.addEdge(label, inV, createProps)
            DefaultTraverser(edge)
        }
    }
}
----

=== 4. `TinkerCatMergeStrategy`

Push `mergeV` search criteria into the index layer to avoid a full vertex scan:

[source,kotlin]
----
class TinkerCatMergeStrategy : TraversalStrategy {
    override fun apply(traversal: GraphTraversal<*, *>) {
        traversal.steps
            .filterIsInstance<MergeVertexStep>()
            .forEach { step ->
                // Rewrite: if a single-property index exists for any search key,
                // replace the linear scan with an index lookup seed
                step.injectIndexSeed(graph)
            }
    }
}
----

|`mergeV_matchesExisting`

|`mergeV_noOnCreate`
|No onCreate option → new vertex created using search criteria directly

|`mergeV_noOnMatch`
|No onMatch option → matched vertex returned unchanged

|`mergeV_idempotent`
|Calling `mergeV` twice with same criteria → second call matches first result

|`mergeE_createsEdge`
|No matching edge → new edge created between specified vertices

|`mergeE_matchesEdge`
|Matching edge found → onMatch properties applied

|`mergeE_requiresLabel`
|Missing `T.label` in criteria → `IllegalArgumentException`

|`mergeV_indexAccelerated`
