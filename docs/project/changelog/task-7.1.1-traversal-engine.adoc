*Upstream Reference*: TinkerPop 3.8.x `GraphTraversalSource`, `GraphTraversal`

TinkerCat was based on TinkerGraph 3.7.x and currently exposes only the structural
graph API (`vertices()`, `edges()`, adjacency-list traversal).
TinkerGraph 3.8.x provides a full Gremlin traversal engine via `graph.traversal()`
returning a `GraphTraversalSource`.
This task implements that engine for TinkerCat in idiomatic Kotlin Multiplatform.

All other Phase 7 traversal-step tasks (7.4.1–7.4.6, 7.5.1–7.5.2, 7.7.1) are blocked
on this task.

== Background

The current query path in TinkerCat is:

----
graph.vertices().asSequence().filter { ... }   // direct iterator
graph.propertyQueryEngine().queryVertices(...)  // PropertyQueryEngine
----

TinkerPop 3.8.x provides a richer, composable query path:

[source,kotlin]
----
val g = graph.traversal()
g.V().hasLabel("person").has("age", P.gte(30)).values("name").toList()
----

The traversal engine decouples query composition from execution, enabling
traversal strategies (index push-down, count short-circuit, etc.) to optimise
the plan before any data is read.

==== `GraphTraversal<S, E>`

A lazy, composable pipeline.
Each step appends a new step object; nothing executes until a terminal step is called.

[source,kotlin]
----
interface GraphTraversal<S, E> : Iterator<E> {
    // Filter steps
    fun hasLabel(vararg labels: String): GraphTraversal<S, E>
    fun has(key: String): GraphTraversal<S, E>
    fun has(key: String, value: Any?): GraphTraversal<S, E>
    fun has(key: String, predicate: P<*>): GraphTraversal<S, E>
    fun hasId(vararg ids: Any?): GraphTraversal<S, E>
    fun hasNot(key: String): GraphTraversal<S, E>
    fun not(traversal: GraphTraversal<*, *>): GraphTraversal<S, E>
    fun where(predicate: P<String>): GraphTraversal<S, E>
    fun dedup(vararg dedupLabels: String): GraphTraversal<S, E>
    fun filter(predicate: P<E>): GraphTraversal<S, E>

    // Traversal steps
    fun out(vararg edgeLabels: String): GraphTraversal<S, Vertex>
    fun `in`(vararg edgeLabels: String): GraphTraversal<S, Vertex>
    fun both(vararg edgeLabels: String): GraphTraversal<S, Vertex>
    fun outE(vararg edgeLabels: String): GraphTraversal<S, Edge>
    fun inE(vararg edgeLabels: String): GraphTraversal<S, Edge>
    fun bothE(vararg edgeLabels: String): GraphTraversal<S, Edge>
    fun outV(): GraphTraversal<S, Vertex>
    fun inV(): GraphTraversal<S, Vertex>
    fun otherV(): GraphTraversal<S, Vertex>

    // Projection steps
    fun values(vararg propertyKeys: String): GraphTraversal<S, Any?>
    fun valueMap(vararg propertyKeys: String): GraphTraversal<S, Map<Any, Any?>>
    fun elementMap(vararg propertyKeys: String): GraphTraversal<S, Map<Any, Any?>>
    fun properties(vararg propertyKeys: String): GraphTraversal<S, out Property<*>>
    fun id(): GraphTraversal<S, Any?>
    fun label(): GraphTraversal<S, String>
    fun key(): GraphTraversal<S, String>
    fun value(): GraphTraversal<S, Any?>

    // Ordering / limiting
    fun order(): GraphTraversal<S, E>
    fun by(key: String): GraphTraversal<S, E>
    fun by(key: String, order: Order): GraphTraversal<S, E>
    fun limit(limit: Long): GraphTraversal<S, E>
    fun range(low: Long, high: Long): GraphTraversal<S, E>
    fun tail(limit: Long = 1): GraphTraversal<S, E>
    fun skip(skip: Long): GraphTraversal<S, E>

    // Side-effect steps
    fun `as`(vararg stepLabels: String): GraphTraversal<S, E>
    fun select(vararg selectKeys: String): GraphTraversal<S, Any?>
    fun path(): GraphTraversal<S, Path>
    fun sideEffect(consumer: (Traverser<E>) -> Unit): GraphTraversal<S, E>
    fun store(sideEffectKey: String): GraphTraversal<S, E>
    fun aggregate(sideEffectKey: String): GraphTraversal<S, E>
    fun group(): GraphTraversal<S, Map<Any?, Any?>>
    fun groupCount(): GraphTraversal<S, Map<Any?, Long>>

    // Mutation steps
    fun addV(label: String): GraphTraversal<S, Vertex>
    fun addE(label: String): GraphTraversal<S, Edge>
    fun property(key: String, value: Any?): GraphTraversal<S, E>
    fun drop(): GraphTraversal<S, E>

    // Terminal steps
    fun toList(): List<E>
    fun toSet(): Set<E>
    fun next(): E
    fun next(amount: Int): List<E>
    fun tryNext(): E?
    fun hasNext(): Boolean
    fun iterate(): GraphTraversal<S, E>
    fun count(): GraphTraversal<S, Long>
    fun sum(): GraphTraversal<S, Number>
    fun min(): GraphTraversal<S, E>
    fun max(): GraphTraversal<S, E>
    fun mean(): GraphTraversal<S, Double>
    fun fold(): GraphTraversal<S, List<E>>
    fun unfold(): GraphTraversal<S, Any?>
    fun explain(): TraversalExplanation
}
----

=== Phase 2: Execution Engine (Weeks 3–6)

The traversal is a linked list of `Step` objects.
Terminal steps pull items through the pipeline lazily.

[source,kotlin]
----
interface Step<S, E> {
    fun processNextStart(): Traverser<E>
    fun addStart(start: Traverser<S>)
    val labels: Set<String>
}
----

Key step implementations:

[cols="2,3", options="header"]
|===
|Step class |Description

|`GraphStep<E>`
|Seed step; reads from `TinkerCat.vertices()` or `.edges()` and applies ID filters

|`HasStep<E>`
|Applies `has()` predicates; cooperates with `TinkerCatStepStrategy` for index push-down

|`VertexStep`
|Traverses adjacency lists using `TinkerVertex.edges()` / `.vertices()`

|`PropertiesStep`
|Emits `Property` or `VertexProperty` objects from the current element

|`ValuesStep`
|Emits raw property values (shorthand for `properties().value()`)

|`OrderGlobalStep`
|Buffers and sorts a complete traversal result set

|`RangeGlobalStep`
|Limits and offsets without buffering more elements than needed

|`DedupGlobalStep`
|Tracks seen objects in a `LinkedHashSet` and filters duplicates

|`CountGlobalStep`
|Counts elements without materialising the full list

|`FoldStep`
|Collects all traversers into a `List`

|`SelectStep`
|Retrieves labelled objects from the traverser path
|===

=== Phase 3: Strategy Framework (Weeks 6–8)

[source,kotlin]
----
interface TraversalStrategy {
    fun apply(traversal: GraphTraversal<*, *>)
}
----

Register strategies in priority order on `GraphTraversalSource`.
Strategies rewrite the step list before execution.

Initial strategies to implement (full detail in tasks 7.5.1 and 7.5.2):

- `TinkerCatStepStrategy` — push `has()` predicates into `GraphStep` for index utilisation
- `TinkerCatCountStrategy` — replace `count()` on bare `V()` / `E()` with map-size reads
